## 开发工作流程


1.chatgpt 网页版用 gpt-5.5pro (进阶专业) 详细讨论需求，让他出一版 prd 或者开发文档初稿。

理由：现在 gpt-5.5pro 的思考深度和信息检索能力顶中顶，很容易帮你找到某项功能的最佳实践，而且文档逻辑性强，非常适合做地基。


1. 把文档拖进 cc，用 mattpocock 的 grill with doc skills 对 prd 进行评审，几十个问题下来，自动同步更新文档，prd 已经可以深化到七八成的落地性（这里用 codex 也行，但是 mattpocock 在 cc 的适配性更好一点）
	
3.cc 和 cx 对 PRD 进行交叉审查，确认最终执行稿，自查一下测试是否完整，如果 token 多可以用 superpowers 的 writing-plan skill 最执行方案。这一项可选可不选，因为有时候会因为计划过长造成注意力丢失的问题，反而执行效果下降。



（如果是新项目：open design给素材和之前的文档写设计）


1. 忙碌了一天的前期准备工作，在晚上临睡前，打开 codex 选择 /goal，把 prd 扔进去，交代 “启用 agent team 并行开发完成所有任务”。然后早上起来就可以收菜了

1. 在这样的前提下，我目前实测 /goal 的完成率大概能到七八成左右，所以还需要至少两轮的 review，分为粗筛和细筛，顺序依次为：
	
打开 cc 用 deepseek 复核完成进度 ———codex 补开发缺口 ——deepseek review——codex 修复 ——codex 打包上传给网页版 gpt5.5pro review——codex 修复 ——cc/cx 交叉核验（可选可不选）—— 人工收尾或 pr```

在**跨域**情况下（父页面与 iframe 页面不同源），无法直接通过 JavaScript 访问对方 DOM 或变量。但可以使用 `**window.postMessage**` API 安全地实现双向通信。


---

## 📡 核心方法：`postMessage`

### 1. 父页面 → iframe 发送消息

```javascript
// 获取 iframe 的 contentWindow 对象
const iframe = document.getElementById('myIframe').contentWindow;

// 发送消息
iframe.postMessage('你好，iframe！', 'https://iframe.example.com');
// 或允许任何来源：'*'（生产环境建议指定确切源）
```

- **第一个参数**：要发送的数据（可以是字符串、对象、数组等，会被结构化克隆）

- **第二个参数**：目标窗口的源（origin），限制接收窗口的来源，防止数据泄露
	
### 2. iframe 内部 → 父页面发送消息

```javascript
// 在 iframe 中
window.parent.postMessage('来自 iframe 的回复', 'https://parent.example.com');
```

### 3. 接收消息（双方都需要监听）

```javascript
window.addEventListener('message', (event) => {
  // 1. 校验来源（安全必须！）
  if (event.origin !== 'https://trusted-domain.com') return;

  // 2. 处理数据
  console.log('收到消息：', event.data);

  // 3. 可选：回复消息（通过 event.source）
  // event.source.postMessage('收到啦', event.origin);
});
```

---

## 🔐 安全要点


| 项目                            | 说明                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------- |
| **始终验证 **`**event.origin**`   | 防止恶意网站伪造消息                                                                                   |
| **避免使用 **`**'*'**`            | 生产环境应指定确切的源（如 `https://a.com`）                                                               |
| **不要信任数据内容**                  | 对收到的数据进行校验、转义，避免 XSS                                                                         |
| **合理使用 **`**sandbox**`** 属性** | 若 iframe 内容不可信，添加 `sandbox="allow-scripts allow-same-origin allow-popups allow-forms"`（按需开放） |

## 📝 完整示例

### 父页面（`https://parent.com`）
```html
<iframe id="childIframe" src="https://child.com/iframe.html"></iframe>

<script>
  const iframeWin = document.getElementById('childIframe').contentWindow;

  // 发送消息
  iframeWin.postMessage({ type: 'greeting', text: 'Hello child' }, 'https://child.com');

  // 接收回复
  window.addEventListener('message', (e) => {
    if (e.origin !== 'https://child.com') return;
    console.log('来自 iframe：', e.data);
  });
</script>
```

### iframe 内容（`https://child.com/iframe.html`）
```html
<script>
  window.addEventListener('message', (e) => {
    if (e.origin !== 'https://parent.com') return;
    console.log('父页面说：', e.data);

    // 回复父页面
    e.source.postMessage('Hello parent!', e.origin);
  });
</script>
```

---

## 🧠 高级用法

- **传递复杂对象**：可直接传对象，如 `{ cmd: 'resize', height: 300 }`

- **动态调整 iframe 高度**：子页面内容变化后，通过 `postMessage` 通知父页面更新 iframe 高度

- **双向 RPC 模式**：封装 `sendAndWait` 函数，利用 `message` 事件 + 临时回调
	
---

## 🚫 不能用其他方式的原因


| 直接访问方式                                       | 是否可行（跨域）   | 说明                 |
| -------------------------------------------- | ---------- | ------------------ |
| `parent.document` / `iframe.contentDocument` | ❌ 否        | 浏览器同源策略阻止          |
| `parent.globalVar`                           | ❌ 否        | 无法访问对方全局对象         |
| `location.hash`                              | ⚠️ 早期 hack | 只能单向传字符串，且会留下历史记录  |
| `window.name`                                | ⚠️ 有限      | 可共享字符串，但机制不直观，有副作用 |
| `**postMessage**`                            | ✅ 推荐       | 安全、双向、任意数据类型、支持跨域  |

## 关键点总结

- Promise 构造函数中的代码是**同步执行**的。

- `**resolve**`** 只能生效一次**，后续的 `resolve` 调用会被忽略。

- 微任务队列在当前同步代码执行完毕后立即清空，清空过程中产生的新微任务也会在本轮清空。

- 宏任务队列中的任务在当前微任务队列完全清空后，才会被取出执行。

## 原始代码

```javascript
const first = () => (new Promise((resolve, reject) => {
    console.log(3);
    let p = new Promise((resolve, reject) => {
        console.log(7);
        setTimeout(() => {
            console.log(5);
            resolve(6);
            console.log(p);
        }, 0);
        resolve(1);
    });
    resolve(2);
    p.then(arg => {
        console.log(arg);
    });
}));

first().then((arg) => {
    console.log(arg);
});

console.log(4);
```

## 逐步分析

### 第 1 步：执行同步代码

- 调用 `first()`，进入外层 Promise 构造函数，立即执行：
	- 输出 `3`
		- 创建内层 Promise `p`，其构造函数立即执行：
		- 输出 `7`
			- 遇到 `setTimeout`，将其回调放入**宏任务队列**
			- 执行 `resolve(1)`，将内层 Promise 状态改为 fulfilled，值为 `1`
			- 执行外层 `resolve(2)`，将外层 Promise 状态改为 fulfilled，值为 `2`
		- 执行 `p.then(arg => { console.log(arg); })`，将回调放入**微任务队列**（因为 `p` 已经 resolved）
	
- 调用 `first().then(...)`，将外层 Promise 的回调放入**微任务队列**

- 执行 `console.log(4)`，输出 `4`
	
此时状态：
```javascript
const first = () => (new Promise((resolve, reject) => {
    console.log(3);
    let p = new Promise((resolve, reject) => {
        console.log(7);
        setTimeout(() => {
            console.log(5);
            resolve(6);
            console.log(p);
        }, 0);
        resolve(1);
    });
    resolve(2);
    p.then(arg => {
        console.log(arg);
    });
}));

first().then((arg) => {
    console.log(arg);
});

console.log(4);
```

```javascript
// 输出：3, 7, 4

微任务队列 = [
    () => { console.log(arg); },          // p.then 的回调，arg = 1
    () => { console.log(arg); }           // first().then 的回调，arg = 2
]

宏任务队列 = [
    () => {
        console.log(5);
        resolve(6);      // 注意：这里的 resolve 是内层 Promise 的 resolve，但内层 Promise 已经 resolved(1)，第二次 resolve 无效
        console.log(p);
    }
]
```

### 第 2 步：执行微任务队列（第一个微任务）


执行 `p.then` 的回调：
- 输出 `1`（因为内层 Promise 的值为 `1`）
	
此时状态：


```javascript
// 输出：3, 7, 4, 1

微任务队列 = [
    () => { console.log(arg); }           // first().then 的回调，arg = 2
]

宏任务队列 = [ 同上，未变 ]
```

### 第 3 步：执行微任务队列（第二个微任务）


执行 `first().then` 的回调：
- 输出 `2`（因为外层 Promise 的值为 `2`）
	
此时状态：


```javascript
// 输出：3, 7, 4, 1, 2

微任务队列 = []

宏任务队列 = [ 同上 ]
```

### 第 4 步：执行宏任务队列


执行唯一的宏任务（`setTimeout` 的回调）：
- 输出 `5`

- 执行 `resolve(6)`：内层 Promise 已经 resolved 为 `1`，再次调用 `resolve(6)` 无效（状态不可变）

- 输出 `p`：此时 `p` 是一个 Promise 对象，其状态为 fulfilled，值为 `1`，因此输出 `Promise { 1 }`（具体输出格式取决于环境，常见为 `Promise { 1 }` 或 `Promise {<fulfilled>: 1}`）
	
此时状态：


```javascript
// 输出：3, 7, 4, 1, 2, 5, Promise { 1 }

微任务队列 = []

宏任务队列 = []
```

## 最终输出顺序


`**3, 7, 4, 1, 2, 5, Promise { 1 }**`


## 关键点总结

- Promise 构造函数中的代码是**同步执行**的。

- `resolve` 只能生效一次，后续的 `resolve` 调用会被忽略。

- 微任务队列在当前同步代码执行完毕后立即清空，清空过程中产生的新微任务也会在本轮清空。

- 宏任务队列中的任务在当前微任务队列完全清空后，才会被取出执行。

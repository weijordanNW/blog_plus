- `**return Promise.resolve(value)**`** 会额外消耗两个微任务（一个用于 **`**Promise.resolve().then(() => value)**`**，另一个用于传递值到下一个 **`**.then**`**）。**

- 微任务队列始终优先于宏任务，且在当前轮次中会彻底清空（但新增的微任务也会在本轮次执行）。

- **链式调用中的每一步都会产生新的微任务，严格遵循先进先出顺序。**


---

# 文档：事件循环进阶（1）

## 原始代码

```javascript
Promise.resolve().then(() => {
    console.log(0);
    return Promise.resolve(4);
}).then((res) => {
    console.log(res)
})

Promise.resolve().then(() => {
    console.log(1);
}).then(() => {
    console.log(2);
}).then(() => {
    console.log(3);
}).then(() => {
    console.log(5);
});
```

## 逐步分析

### 第 1 步：初始状态


同步代码执行完毕，两个 `Promise.resolve().then` 的回调均被放入微任务队列。


```javascript
// 输出：（暂无）

微任务队列 = [
    () => {
        console.log(0);
        return Promise.resolve(4);
    }.then((res) => { console.log(res) }),   // 第一个 Promise 链
    () => {
        console.log(1);
    }.then(() => {
        console.log(2);
    }).then(() => {
        console.log(3);
    }).then(() => {
        console.log(5);
    })
]

宏任务队列 = []
```

### 第 2 步：执行第一个微任务


取出第一个微任务执行：
- 输出 `0`

- `return Promise.resolve(4)` 会隐式产生新的微任务（相当于 `Promise.resolve().then(() => 4).then(...)`），导致后续的 `console.log(res)` 被推迟到下一个微任务。
	
```javascript
// 输出：0

微任务队列 = [
    () => {
        console.log(1);
    }.then(() => {
        console.log(2);
    }).then(() => {
        console.log(3);
    }).then(() => {
        console.log(5);
    }),
    // 新添加的微任务（由 return Promise.resolve(4) 产生）
    Promise.resolve().then(() => 4).then((res) => { console.log(res) })
]

宏任务队列 = []
```

### 第 3 步：执行第二个微任务（原本的第二条 Promise 链的第一个回调）


执行 `console.log(1)` 的回调：
- 输出 `1`

- 该回调返回 `undefined`，所以其 `.then(() => console.log(2))` 会进入微任务队列。
	
此时微任务队列状态：


```javascript
// 输出：0, 1

微任务队列 = [
    // 由 return Promise.resolve(4) 链产生的微任务（待展开）
    Promise.resolve().then(() => 4).then((res) => { console.log(res) }),
    // 第二条 Promise 链的下一个回调
    () => { console.log(2) }.then(() => { console.log(3) }).then(() => { console.log(5) })
]
```


实际上，`Promise.resolve().then(() => 4).then((res) => { console.log(res) })` 本身又是一个微任务链，会在当前轮次逐步展开。


### 第 4 步：继续处理微任务队列（展开返回值链）


执行 `Promise.resolve().then(() => 4).then((res) => { console.log(res) })` 的第一个微任务（即 `() => 4`）：
- 该微任务直接返回值 `4`，然后其 `.then((res) => console.log(res))` 被加入微任务队列。
	
```javascript
// 输出：0, 1

微任务队列 = [
    () => { console.log(2) }.then(() => { console.log(3) }).then(() => { console.log(5) }),
    () => { console.log(4) }   // 这是由前一个微任务产生的新的微任务
]
```

### 第 5 步：执行 `console.log(2)` 的回调

- 输出 `2`

- 其后的 `.then(() => console.log(3))` 被加入微任务队列。
	
```javascript
// 输出：0, 1, 2

微任务队列 = [
    () => { console.log(4) },
    () => { console.log(3) }.then(() => { console.log(5) })
]
```

### 第 6 步：执行 `console.log(4)`

- 输出 `4`
	
```javascript
// 输出：0, 1, 2, 4

微任务队列 = [
    () => { console.log(3) }.then(() => { console.log(5) })
]
```

### 第 7 步：执行 `console.log(3)`

- 输出 `3`

- 其后的 `.then(() => console.log(5))` 被加入微任务队列。
	
```javascript
// 输出：0, 1, 2, 4, 3

微任务队列 = [
    () => { console.log(5) }
]
```

### 第 8 步：执行 `console.log(5)`

- 输出 `5`
	
```javascript
// 输出：0, 1, 2, 4, 3, 5

微任务队列 = []
宏任务队列 = []
```

## 最终输出顺序


`**0, 1, 2, 4, 3, 5**`



> **注意**：部分资料中可能显示为 `0,1,2,3,4,5`，但根据 Promise 规范中 `return Promise.resolve(4)` 的处理方式（会产生两个额外的微任务），实际顺序应为 `0,1,2,4,3,5`。以上逐步分析基于标准事件循环机制得出。


## 关键结论

- `return Promise.resolve(value)` 会额外消耗两个微任务（一个用于 `Promise.resolve().then(() => value)`，另一个用于传递值到下一个 `.then`）。

- 微任务队列始终优先于宏任务，且在当前轮次中会彻底清空（但新增的微任务也会在本轮次执行）。

- 链式调用中的每一步都会产生新的微任务，严格遵循先进先出顺序。

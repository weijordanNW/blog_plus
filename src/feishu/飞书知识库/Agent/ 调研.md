# 面试题总结分析报告

## 核心结论


**市场上的“前端”已经悄悄变成了“AI 应用全栈岗”。**



13家公司中仅SH一家在问纯前端八股，其余全部聚焦AI工程、后端、基础设施和落地能力。




## 一、高频考点排序（按出现公司数）

### 1. RAG全链路（5家：JR、TK、PY、HQ、YU）
- 分片入库 / 向量库选型 / 混合检索 / Re-rank

- 查询改写 / 召回准确性验证

- ⚠️ “已经排序去重了为什么还要排序”——面试官自己做过，追问很细
	
### 2. AI工作流与效率量化（5家：YC、HJ、XZ、PY、YU）
- 个人怎么用AI开发 / 用什么MCP/Skill

- 效率提升百分比 / AI代码怎么review

- 🎯 筛选“真正把AI融入日常工作的人”，而非只会调用API
	
### 3. 测试通信（4家：YC、FH、SH、HQ）
- SSE vs WebSocket / 断线重传 / 心跳重连 / 边接收边渲染

- 这是AI产品前端的标配技能
	
### 4. Multi-Agent架构（3家：ML、JR、HQ）
- 反复追问“agent也能多智能，为什么要多Agent”

- 考察你是做多架构还是做多智能
	
### 5. 后端硬实力（4家：KJ、TK、PY、HQ）
- MySQL慢查询/大表优化 / 消息队列不丢任务

- 缓存一致性 / 秒杀超卖 / Docker/K8s
		
## 二、值得注意的信号


| 信号                   | 说明                                                         |
| -------------------- | ---------------------------------------------------------- |
| **Claude Code成为面试题** | KJ和JR在问多层级树、上下文治理、核心循环，甚至“泄露事件有没有研究过源码”——一线AI工具的内部原理已成考察素材 |
| **量化数据被反复追问**        | 用户量/日活/token月消耗/降本多少/ROI/最大并发——至少4家在问数字，说不清会被识破含水量         |
| **可观测性工程是隐藏主线**      | AI调用失败怎么办/SSE断了怎么续/队列挂了怎么一致/长任务怎么断点续跑——demo选手和生产线选手的分界线    |
| **小团队一人多角色**         | “UI没出图你怎么推进”“没有测试怎么测试”“没有PM怎么出PRD”——4家公司出现，期望你用AI补齐缺口      |
| **成本意识是新人标配**        | ML和HQ都在问怎么降token成本、避免重复推理——毛利问题已传导到一线面试                    |




## 三、备考优先级建议

1. **RAG全链路深度叙事**：准备20分钟讲述，每个环节覆盖“为什么这么选 + 踩过什么坑 + 数据效果”
	
1. **补齐量化口径**：日活 / token量 / 成本对比 / 效率提升百分比——估算也要有逻辑支撑
	
1. **整理AI开发工作流**：工具链 + MCP/Skill + Code Review机制——每家都可能问的开放题，最易拉开差距
	
1. **准备2-3个“故障兜底”故事**：工具调用失败 / 流断线 / 队列任务丢失的处理方案
	
1. **前端八股别完全丢**：Vue2/3响应式 / SSE/WS / 浏览器兼容——仍是穿插出现的保底盘
		
## 理想候选人画像


> 有真实AI项目落地数据 + 能讲清RAG和Multi-Agent架构权衡 + 后端能扛MySQL/队列/K8s + 还能用AI一人顶起小组队



**——这就是当前市场在招的“AI应用全栈工程师”**

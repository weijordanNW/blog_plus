## 图

# 🧠 RAG 知识体系整理


> **RAG = Retrieval-Augmented Generation = 检索增强生成**    
> 核心思想：**先检索外部知识，再让大模型基于参考资料生成答案。**


---
## 一、为什么需要 RAG？

### 1. 大模型的生产流程

```plaintext
数据爬取 → 数据清洗 → 数据预处理 → 模型训练 → 模型推理
```


特点：



| 特点   | 说明            |
| ---- | ------------- |
| 单向流程 | 从数据到模型，一路向前   |
| 耗时   | 数据爬取、清洗、训练都很慢 |
| 算力大  | 即使小模型，训练成本也不低 |
| 一次成型 | 训练完成后，知识基本固化  |


### 2. 大模型的两大短板


| 短板   | 具体表现               | 后果             |
| ---- | ------------------ | -------------- |
| 数据陈旧 | 知识有截止日期            | 问新事件容易不知道或产生幻觉 |
| 数据不全 | 内网、机密、实时、专业、小众知识缺失 | 垂直领域回答泛泛而谈     |



原文提到：


- Claude 数据更新到 2023 年 8 月

- DeepSeek R1 预训练数据更新到 2023 年 12 月

- GPT-4O、Llama 3.3 原文提到 10 月

## 二、RAG 是什么？


> **RAG 是一种将“检索系统”与“生成式 AI”结合的技术。**    
> 通过从知识库中检索相关信息，增强 AI 模型的回答，使其更准确、更新、可溯源。



简单两步：


1. **检索**：把用户问题向量化，在向量数据库中找最相关文档；

1. **生成**：把相关文档 + 原始问题拼进提示词，交给大模型生成答案。
	
---

## 三、RAG 的三大组件


| 组件 | 作用               |
| -- | ---------------- |
| 检索 | 从知识库中找到与问题最相关的信息 |
| 增强 | 把检索结果嵌入提示词，优化上下文 |
| 生成 | 大模型基于增强后的提示词输出答案 |


---

## 四、RAG 完整流程

```plaintext
【入库】
文档 / 实时信息 / 专业知识
        ↓
     向量化
        ↓
   向量数据库

【查询】
用户问题
   ↓
 向量化
   ↓
向量数据库检索
   ↓
最相关文档块
   ↓
增强提示词
   ↓
提交大模型
   ↓
生成答案
```


| 阶段 | 关键动作  | 说明            |
| -- | ----- | ------------- |
| 入库 | 文档向量化 | 用嵌入模型把文档变成向量  |
| 检索 | 问题向量化 | 在向量空间中找语义最近的点 |
| 增强 | 拼提示词  | 把相关文档塞进提示词模板  |
| 生成 | 大模型回答 | 基于问题 + 参考资料输出 |

## 五、为什么用向量数据库？


| 类型              | 搜索方式  | 特点                  |
| --------------- | ----- | ------------------- |
| MySQL / MongoDB | 关键词匹配 | 像传统搜索引擎，效率低，难理解完整语义 |
| 向量数据库           | 语义相似度 | 比较向量距离，越近越相关        |



> 向量搜索比较的是“语义相关性”，不是单纯“词是否命中”。



例如：


- 猫、狗、宠物 → 语义接近

- 牛、羊、家畜 → 语义接近

- 它们都属于动物，因此比“柜子、砖头”更接近

## 六、两个直观例子

### 例 1：北京天气


用户问：“北京此刻天气如何？”


1. 调用天气 API；

1. 把温度、湿度、紫外线、空气指数向量化入库；

1. 检索相关天气信息；

1. 拼进提示词；

1. 大模型生成：“北京今天天气很好，温度适宜，适合郊游。”
	
### 例 2：法律专利案件


用户问专业专利案件问题。


1. 预训练模型可能没有相关判例；

1. 在向量数据库放入专利案件判例；

1. 检索最相关判例；

1. 拼进提示词；

1. 大模型基于判例生成更专业的回答。

| 问题               | 结论         |

| RAG 是智能体开发的必选项吗？ | 不是         |
| RAG 是能力增强的必选项吗？  | 是          |
| RAG 能独立做应用吗？     | 可以         |
| RAG 能作为智能体工具吗？   | 可以，甚至是核心工具 |



> 如果希望智能体能力更强、体验更好，通常需要加入 RAG。


---

## 八、核心总结


> **输入决定输出。**    
> RAG 的本质，是通过检索外部知识来增强大模型生成质量。



关键环节：


1. 数据处理

1. 向量化

1. 嵌入模型

1. 向量数据库

1. 检索策略与召回率

1. 提示词增强

1. 大模型生成
	
**一句话：RAG = 先检索，再增强，最后生成。**

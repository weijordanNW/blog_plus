# 🗄️ 向量艺术：向量数据库基础


> **核心一句话：向量数据库是 RAG 的关键组件——存储外挂知识，通过相似度搜索找到与问题最相关的文档片段。**


---

## 一、向量数据库在 RAG 中的位置

```plaintext
用户问题
   ↓
嵌入模型 → 问题向量坐标
   ↓
向量数据库
   ↓
相似度搜索 → 找到最接近的文档片段
   ↓
返回文档碎片集合
```


作用总结：



| 步骤 | 说明                |
| -- | ----------------- |
| 1  | 问题被嵌入向量化后，进入向量库   |
| 2  | 使用向量搜索找到相关文档片段    |
| 3  | 返回文档碎片集合，供后续增强提示词 |



> 向量数据库存储了所有外挂知识，是 RAG 中匹配问题与参考资料的重要容器。


---

## 二、向量数据库的关键特性


| 特性   | 说明                       |
| ---- | ------------------------ |
| 存储内容 | 高维向量数据（embedding 后的坐标）   |
| 记录形式 | 每条记录通常是一个向量（数组）          |
| 数据模式 | 灵活，不强制预定义 schema         |
| 存储本质 | 数据的特征表示、表征               |
| 核心操作 | 相似度搜索，而非精确匹配             |
| 关键算法 | 内置检索算法决定检索效果，如稀疏算法、ANN 等 |



> 不同向量数据库内置的检索算法不同，选型时需关注其支持的算法能力。


---

## 三、向量数据库 vs 关系型数据库

### 1. 存储方式对比


| 对比项  | 关系型数据库（如 MySQL） | 向量数据库             |
| ---- | --------------- | ----------------- |
| 存储内容 | 结构化数据           | 向量数据              |
| 数据形式 | 表格、多字段记录        | 高维向量、数组           |
| 数据模式 | 需符合预定义 schema   | 灵活，可存多种模式         |
| 存储本质 | 具体值             | 数据的特征表示           |
| 示例   | 员工工资表，具体数值      | 文本 embedding 后的坐标 |


### 2. 查询方式对比


| 对比项  | 关系型数据库       | 向量数据库                  |
| ---- | ------------ | ---------------------- |
| 查询类型 | 精确查询         | 相似度搜索                  |
| 查询语言 | SQL          | 向量检索 API               |
| 匹配方式 | 精确匹配         | 按相似程度搜索                |
| 底层索引 | B树、哈希等       | 向量空间距离计算               |
| 常见操作 | WHERE、JOIN 等 | 最近邻查询、欧式距离、余弦相似度、ANN 等 |


### 3. 应用场景对比


| 对比项  | 关系型数据库                | 向量数据库                         |
| ---- | --------------------- | ----------------------------- |
| 主要场景 | 事务处理                  | 高性能检索                         |
| 典型应用 | 业务数据管理、交易处理、用户信息、订单管理 | 图像相似度搜索、文本语义搜索、推荐系统、AI/ML 应用  |
| 性能优势 | 擅长事务处理、复杂表间关系、多表联合查询  | 优化高维向量存储与检索，支持快速相似度计算、大规模向量检索 |
| 部署   | 传统部署                  | 通常支持分布式部署                     |


---

## 四、为什么不用 MySQL 存向量？


| 原因       | 说明                       |
| -------- | ------------------------ |
| 无法做相似性搜索 | MySQL 是精确匹配，无法按语义相似度检索   |
| 效率低      | 即使勉强实现，效率也远低于向量数据库       |
| 场景不匹配    | RAG 需要的是“相似度搜索”，不是“精确查询” |



> 不要把向量数据库和关系型数据库搞混。它们的设计目标、存储方式、查询方式完全不同。


---

## 五、向量数据库选型注意事项


| 注意点          | 说明                            |
| ------------ | ----------------------------- |
| 支持的检索算法      | 是否支持高级算法，直接影响检索效果             |
| LangChain 封装 | LangChain 封装了统一接口，但底层不支持则调用无效 |
| 分布式部署        | 大规模场景需关注是否支持分布式               |
| 与嵌入维度匹配      | 向量维度必须与嵌入模型输出维度一致             |


---

## 六、一句话总结


> **向量数据库不是传统数据库的替代品，而是为“相似度搜索”而生的专用组件。**    
> 它存储 embedding 后的向量坐标，通过内置算法快速找到与问题最相关的文档片段，是 RAG 系统中连接“检索”与“生成”的关键桥梁。

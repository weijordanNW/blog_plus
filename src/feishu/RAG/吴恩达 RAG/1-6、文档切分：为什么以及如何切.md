# ✂️ 文档切分：为什么切？怎么切？


> **核心一句话：切分是为了适配模型上下文窗口，同时提升检索效率。**    
> 切分的终极目标：让每个切片尽量是一个**独立的语义单元**。


---

## 一、为什么要切分文档？


| 原因       | 说明                        |
| -------- | ------------------------- |
| **主要原因** | 模型有上下文窗口长度限制，不能直接塞入整本书    |
| **次要原因** | 大文档块检索效率低，容易命中不到或难以找到相关内容 |



所以，切分是 RAG 系统中非常重要的一步。


---

## 二、切分策略有哪些？

### 1. 基于长度切分


| 项目 | 说明                            |
| -- | ----------------------------- |
| 做法 | 设定固定长度，如每 100 个 token 一块，直接裁剪 |
| 优点 | 简单、暴力、直接                      |
| 缺点 | 可能破坏文本语义联系，一段话被切成两半           |
| 后果 | 检索时可能只命中一半，模型拿到残缺参考资料         |


```plaintext
原始段落 → 一刀切 → 片段1 + 片段2
```

---

### 2. 基于文本架构切分


| 项目 | 说明                  |
| -- | ------------------- |
| 做法 | 按段落或句子切分            |
| 优点 | 比长度切分更“温柔”，保留完整语义架构 |
| 效果 | 每个切片通常是完整一段话或完整一句话  |


```plaintext
文档 → 按段落切分 → 段落1 + 段落2 + 段落3
```

---

### 3. 基于文档格式切分


| 项目 | 说明                         |
| -- | -------------------------- |
| 做法 | 根据文档格式切分，如 Markdown、JSON 等 |
| 优点 | 尽量保证切片是独立的语义单元             |
| 示例 | Markdown 按标题层级切，JSON 按字段切  |


---

### 4. 基于语义智能切分


| 项目 | 说明                        |
| -- | ------------------------- |
| 做法 | 引入模型，对文档进行语义层面的切分         |
| 目标 | 这一块讲第一个意思，那一块讲第二个意思，就切成两片 |
| 优点 | 切片语义独立，检索质量高              |
| 代价 | 需要模型参与，成本更高               |



> 这是比较优质的切分方式，也是终极目标。


---

## 三、切分策略对比


| 策略     | 依据                | 优点       | 缺点      |
| ------ | ----------------- | -------- | ------- |
| 基于长度   | 固定 token 数        | 简单暴力     | 易破坏语义联系 |
| 基于文本架构 | 段落 / 句子           | 保留完整语义   | 依赖文本结构  |
| 基于文档格式 | Markdown / JSON 等 | 切片相对独立   | 格式受限    |
| 基于语义   | 模型语义分析            | 语义独立，质量高 | 成本较高    |


---

## 四、一句话总结


> **切分不是随便切，而是为了让每个片段既适配模型窗口，又保留完整语义。**    
> 从“按长度”到“按语义”，策略越精细，检索效果通常越好。

# 📥 RAG 输入部分：LangChain 数据预处理全流程


> **核心观点：好的输入与数据处理，是 RAG 实现的基础。**    
> 文档向量化，是进行向量搜索的前置条件。



> 对应 **RAG / LangChain / Loader / Splitter**。


---

## 一、RAG 输入预处理的核心流程

```plaintext
【数据源】
网页 / PDF / 图片 / Excel / JSON / URL / 邮件 / 视频 ...
        ↓
【Loader 加载】
把各种格式的数据加载进系统
        ↓
【Splitter 切片】
把大文档切成小片段
        ↓
【Embedding 嵌入】
用嵌入模型把切片向量化
        ↓
【Vector Store 向量存储】
把向量坐标存入向量数据库
        ↓
【Retriever 检索】
后续通过向量搜索找到相关文档块
```

---

## 二、四个关键步骤


| 步骤      | 英文           | 作用                | 关键点               |
| ------- | ------------ | ----------------- | ----------------- |
| 1. 文件加载 | Loader       | 把不同来源、不同格式的数据加载进来 | 漏斗越大越好，支持格式越多越好   |
| 2. 文档切片 | Splitter     | 把大文档切成小片段         | 模型有上下文窗口，不能直接塞整本书 |
| 3. 向量化  | Embedding    | 把文本片段变成向量坐标       | 由嵌入模型完成，不同模型能力不同  |
| 4. 向量存储 | Vector Store | 把向量坐标存入向量数据库      | 为后续向量搜索做准备        |


---

## 三、为什么必须切片？


因为所有模型都有 **上下文窗口 / Context Window**。



即使某些模型号称上下文窗口很大，也仍然是有限的。



如果直接丢一本书进去：


```plaintext
大文档 → 模型上下文窗口溢出 → 无法处理
```


所以必须：


```plaintext
大文档 → 切片 → 小片段 → 便于模型处理与向量化
```

---

## 四、嵌入模型的重要注意点


嵌入模型不是都一样的，不同模型能力不同。



| 问题     | 说明                             |
| ------ | ------------------------------ |
| 语言支持不同 | 有的只训练了中文，没训练英文，就无法很好嵌入英文文档     |
| 向量维度不同 | 有的只支持 1024 维，就不能直接嵌入到 3072 维空间 |
| 能力差异   | 不同嵌入模型对应的语义表达能力不同              |



> 选择嵌入模型时，要关注：**语言支持、向量维度、模型能力**。

## 五、LangChain 中的实现方式


LangChain 的整体逻辑与通用 RAG 一致：


```plaintext
文档 → Loader → 切片 → 向量化 → 向量存储 → 向量检索
```

### 1. Loader 加载环节


LangChain 做了大量封装，并开放社区生态。



目前支持市面几乎所有主流数据：



| 数据类型  | 示例                 |
| ----- | ------------------ |
| 网页    | Web Loader         |
| 文档    | Markdown、PDF、PPT   |
| 结构化数据 | CSV、JSON           |
| 社交/媒体 | 邮件、Twitter、YouTube |
| 协作平台  | Notion、网盘数据        |



优势：


- 不用自己写复杂加载机制；

- 网页 Loader 甚至封装了类似爬虫与解析逻辑；

- 可直接使用现成组件。
	
### 2. Transform / 切片环节


对应文档切片。



LangChain 提供多种切片工具：


- 支持不同文档类型；

- 支持不同切片格式要求；

- 把大文档切成适合模型处理的小块。
	
### 3. Embedding 向量化环节


LangChain 支持市面上主流的嵌入模型。



使用方式：


```plaintext
文档切片 → Embedding 模型 → 向量坐标
```

### 4. Vector Store 向量存储环节


LangChain 已支持接入主流向量数据库。



方便实现：


- 增；

- 删；

- 查；

- 检索。
	
---

## 六、LangChain 输入预处理总结


| 环节           | LangChain 能力 | 开发体验        |
| ------------ | ------------ | ----------- |
| Loader       | 社区包丰富，支持多格式  | 几乎不用自己写复杂加载 |
| Splitter     | 多种切片工具       | 适配不同文档与格式   |
| Embedding    | 支持主流嵌入模型     | 方便向量化       |
| Vector Store | 支持主流向量数据库    | 方便存储与检索     |
| 自定义          | 可根据需要自定义     | 但封装组件通常已够用  |


---

## 七、一句话总结


> **LangChain 把 RAG 的输入预处理流程标准化、生态化。**    
> 开发者只需组合 Loader、Splitter、Embedding、Vector Store 等组件，就能完成从数据加载到向量存储的全过程，为后续检索与生成打好基础。

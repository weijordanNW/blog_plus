# 🧬 向量艺术：嵌入模型（Embedding）


> **核心一句话：嵌入模型是 RAG 的“翻译器”——把文本翻译成向量空间中的坐标，让语义相似度可以用数学计算。**


---

## 一、向量化在 RAG 中的位置


前面已经完成：


```plaintext
Loader 加载 → 文档切分 → Document 列表
```


接下来就是：


```plaintext
Document 列表 → Embedding → 向量坐标 → 向量数据库
```


整体流程：


```plaintext
【入库阶段】
文档 → 切分 → Document 列表
        ↓
    嵌入模型 Embedding
        ↓
    向量坐标
        ↓
    向量数据库

【查询阶段】
用户问题
   ↓
嵌入模型 Embedding
   ↓
问题向量坐标
   ↓
相似性搜索
   ↓
找到最相关的文档
```

---

## 二、嵌入模型的作用


| 项目      | 说明                |
| ------- | ----------------- |
| 本质      | 把文本转化为数字向量表示      |
| 目的      | 用数字运算比较文本之间的语义相似度 |
| 地位      | 向量化的核心            |
| 输出      | 一组高维坐标            |
| 在 RAG 中 | 把所有输入统一变成向量坐标     |



> 嵌入模型不是用来生成文字的，而是用来**表示语义**的。


---

## 三、为什么需要嵌入模型？


因为 RAG 需要在向量空间中进行语义搜索。



| 对比 | 传统搜索         | 向量搜索               |
| -- | ------------ | ------------------ |
| 方式 | 关键词匹配        | 语义相似度              |
| 例子 | 搜“猫”，只能匹配“猫” | 搜“猫”，可能匹配“宠物”“喵星人” |
| 依赖 | 词是否命中        | 向量距离是否接近           |
| 效果 | 难理解完整语义      | 能理解语义相关性           |



嵌入模型就是完成“文本 → 向量”的关键组件。


---

## 四、常见相似度算法


向量数据库通常会封装这些算法：



| 算法     | 衡量方式           | 特点            |
| ------ | -------------- | ------------- |
| 余弦相似度  | 两个向量夹角的余弦值     | 关注方向，适合文本语义比较 |
| 欧几里得距离 | 两点之间的直线距离      | 关注绝对距离        |
| 点积     | 一个向量在另一个向量上的投影 | 同时受方向和长度影响    |



> 一般不需要自己实现，向量数据库已经封装好了。


---

## 五、LangChain 在嵌入环节做了什么？


LangChain 的核心工作是：**抹平接口**。



| 问题         | LangChain 的解决       |
| ---------- | ------------------- |
| 嵌入模型太多     | 封装统一标准接口            |
| 不同模型调用方式不同 | 提供一致的 Embeddings 接口 |
| 切换模型麻烦     | 改配置即可切换             |
| 维度、厂商差异    | 由 LangChain 适配层处理   |



> 你只需要调用 LangChain 的嵌入接口，不用关心底层模型差异。

## 七、嵌入模型在 RAG 中的完整意义

```plaintext
文档 → 嵌入 → 向量坐标 → 存入向量数据库
问题 → 嵌入 → 向量坐标 → 相似性搜索 → 找到相关文档
```


所以：


- 没有嵌入模型，就无法做向量搜索；

- 嵌入模型决定了文本在向量空间中的坐标；

- 坐标越准，检索越准；

- 检索越准，RAG 回答质量越高。
	
---

## 八、一句话总结


> **嵌入模型是 RAG 的语义基石。**    
> 它把文档和问题统一转换成向量坐标，让“语义相似”变成“向量距离近”，从而支撑向量数据库中的相似性搜索。



> LangChain 的价值在于：**封装海量嵌入模型，提供统一接口，让开发者方便切换和使用。**

# ✂️ LangChain 文档切分实战：长度、文本、文档格式与语义切片


> **核心一句话：切分的目标是让每个切片尽量成为独立语义单元，同时适配模型上下文窗口。**    
> 生产环境最常用：**基于长度、基于文本架构、基于文档格式**。    
> 基于语义切分属于实验性用法，不建议直接上生产。


---

## 一、基于长度切分

### 1. 核心思路


不管文档内容，直接按固定 token 长度裁剪。


### 2. 实现方式


安装依赖：


```bash
pip install langchain-text-splitters
```


加载文档后，使用按长度的切分器：


```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
    encoding_name="cl100k_base",
    chunk_size=50,
    chunk_overlap=0
)
```

### 3. 关键参数


| 参数              | 说明                |
| --------------- | ----------------- |
| `chunk_size`    | 每个切片的 token 长度    |
| `chunk_overlap` | 相邻切片之间的重叠 token 数 |


### 4. 重叠参数的区别


| 设置                 | 效果                          |
| ------------------ | --------------------------- |
| `chunk_overlap=0`  | 切片之间无交集，第一片结束就是第二片开始        |
| `chunk_overlap=10` | 相邻切片有 10 个 token 的重叠，上下文更连贯 |



> 重叠可以让检索时更容易命中完整语义，减少信息断裂。

## 二、基于文本架构切分

### 1. 核心思路


按段落或句子切分，保证每个切片是完整的语义架构。


### 2. 实现方式


使用 `RecursiveCharacterTextSplitter` 或 `CharacterTextSplitter`：


```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=20
)
chunks = splitter.split_text(text)
```

### 3. 效果

- 每个切片通常是一句完整的话或一个完整段落；

- 不会出现一句话从中间被劈开的情况。
	
### 4. 注意事项


> 它依赖原文中的段落结构。    
> 如果原文没有段落、句子也没有明显分隔，它就无法识别语义边界。



例如：


- 原文有三段 → 切出三个切片；

- 原文三段连在一起没有格式 → 无法正确识别。

## 三、基于文档格式切分

### 1. Markdown 切分


按 Markdown 标题层级切分：


- `#` 一级标题；

- `##` 二级标题；

- `###` 三级标题。
	
```python
from langchain_text_splitters import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#", "Header 1"),
    ("##", "Header 2"),
    ("###", "Header 3"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on
)
chunks = splitter.split_text(markdown_text)
```


效果：


- 一级标题、二级标题、三级标题都会作为切分依据；

- 每个切片保留对应标题结构。
	
### 2. JSON 切分


按 JSON 对象或数组内容切分。


```python
from langchain_text_splitters import RecursiveJsonSplitter

splitter = RecursiveJsonSplitter(max_chunk_size=300)
chunks = splitter.split_json(json_data)
```


效果：


- 按数组元素或对象字段切分；

- 尽量保证每个切片是完整字段或完整元素。
	
### 3. 转为 Document 对象


切分后可以用 `create_documents` 直接转成 LangChain 的 `Document` 对象：


```python
docs = splitter.create_documents(chunks)
```


> 转成 `Document` 后，就可以直接进入嵌入、向量化环节。

## 四、基于语义切分

### 1. 核心思路


最高级的切分方式：从文本中识别语义，保证每个切片是独立语义主体。


### 2. 实现方式


使用 `SemanticChunker`：


```python
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings()
splitter = SemanticChunker(embeddings)
chunks = splitter.split_text(text)
```

### 3. 特点


| 项目  | 说明                       |
| --- | ------------------------ |
| 包位置 | `langchain_experimental` |
| 性质  | 实验性功能                    |
| 依赖  | OpenAI 向量化               |
| 效果  | 按语义主体切分，切片质量高            |
| 建议  | **不建议生产环境使用**            |



> 原文强调：生产环境更常用的是长度、文本架构、文档格式这三种。


---

## 五、四种切分方式对比


| 切分方式   | 依据              | 优点       | 缺点       | 生产建议     |
| ------ | --------------- | -------- | -------- | -------- |
| 基于长度   | 固定 token 数      | 简单直接     | 易破坏语义    | ✅ 常用     |
| 基于文本架构 | 段落 / 句子         | 保留完整语义   | 依赖原文段落结构 | ✅ 常用     |
| 基于文档格式 | Markdown / JSON | 切片相对独立   | 受格式限制    | ✅ 常用     |
| 基于语义   | 模型语义分析          | 语义独立，质量高 | 实验性，成本高  | ⚠️ 不建议生产 |


---

## 六、一句话总结


> **长度切分简单粗暴，文本架构切分保留语义，文档格式切分尊重结构，语义切分最高级但实验性。**    
> 实际开发中，优先掌握 **长度、文本架构、文档格式** 三种切分器；    
> 语义切分可作为进阶了解，暂不建议直接用于生产环境。
